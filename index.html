Part I

Pipelining & Branch Prediction

How microprocessors achieve Instruction-Level Parallelism (ILP): classical 5-stage RISC hazards, saturating counter FSMs, Tomasulo out-of-order execution, and AVX-512 vector pipelines.

01 Pipeline Hazards

Classic 5-Stage RISC Pipeline & Data Forwarding

The classical RISC microprocessor breaks instruction execution into 5 discrete stages: Instruction Fetch (IF), Instruction Decode / Register Read (ID), Execute / Address Calculation (EX), Memory Access (MEM), and Write Back (WB).

Under a naive implementation, a Read-After-Write (RAW) data dependency (e.g. ADD R1, R2, R3 followed immediately by SUB R4, R1, R5) forces the pipeline to insert 2 NOP bubbles (stall cycles) waiting for $R_1$ to reach the WB stage. Modern microarchitectures implement Data Forwarding (Bypassing): multiplexers route the computed ALU result directly from the output of the EX or MEM stage back into the EX input of the dependent instruction, eliminating pipeline stalls completely!

02 Branch Prediction

Dynamic Branch Prediction: 2-Bit Saturating Counters & BTB

In deep pipelines (14 to 20 stages on modern Intel and AMD cores), conditional branches (if/else, while) pose a catastrophic latency hazard: waiting until the branch condition resolves in the EX stage would stall the processor for 15+ cycles on every branch!

Microarchitectures employ Dynamic Branch Prediction with 2-Bit Saturating Counters. The counter requires two consecutive mispredictions to flip its prediction (e.g. from Strongly Taken $\rightarrow$ Weakly Taken $\rightarrow$ Weakly Not Taken). This ensures that loop back-edges only mispredict once upon loop exit rather than thrashing the predictor state. When combined with a Branch Target Buffer (BTB), instructions along the predicted path are fetched with zero stall cycles.

03 Out-of-Order (OoO)

Out-of-Order Execution: Tomasulo's Algorithm & Reorder Buffer (ROB)

To extract maximum performance from multi-issue superscalar cores, modern processors abandon in-order execution. Tomasulo's Algorithm dispatches instructions to Reservation Stations where they wait for their operands. When an operand becomes available, it is broadcast over the Common Data Bus (CDB), allowing instructions to execute out of program order as soon as their data dependencies are satisfied.

To maintain Precise Interrupts (the architectural illusion that instructions execute sequentially), results are written speculatively into a circular FIFO queue called the Reorder Buffer (ROB). Instructions commit to permanent architectural registers strictly in original program order from the head of the ROB!

04 SIMD Vectorization

SIMD Vector Execution: AVX-512 & Vector Masking

While scalar execution units process one word per clock cycle, Single Instruction Multiple Data (SIMD) execution units pack multiple data elements into wide vector registers (e.g. 512-bit ZMM registers in AVX-512).

A single 512-bit instruction can perform 16 parallel single-precision floating-point operations (or 32 with Fused Multiply-Add, FMA) in one clock cycle! AVX-512 introduced Vector Opmask Registers ($k_1\text{--}k_7$): by applying bitmasks, conditional if/else code is executed vectorially without branch instructions, completely eliminating branch misprediction penalties.

Part II

Memory Hierarchy & Cache Coherence

How multi-core processors maintain consistent memory state: cache geometry indexing, the MESI snooping protocol, false sharing pitfalls, and x86 TSO memory barriers.

05 Cache Geometry

Cache Geometry: Tag / Index / Offset & The 3 C's of Cache Misses

A CPU cache is organized into lines (almost universally 64 bytes). A virtual or physical memory address is divided into three bitfields:

  • Offset (lowest 6 bits): Identifies the exact byte within the 64-byte line ($2^6 = 64$).
  • Set Index (middle $s$ bits): Selects which set in the cache will store the line ($2^s = \text{number of sets}$).
  • Tag (highest bits): Stored alongside data in the cache to verify that the cached line matches the requested memory address.

Mark Hill and Alan Jay Smith established the 3 C's Classification for cache misses: Compulsory (Cold) (unavoidable first touch), Capacity (working set exceeds total cache size), and Conflict (multiple addresses map to the exact same set index, mitigated by increasing associativity to 8-way or 16-way).

06 Cache Coherence

The MESI Cache Coherence Protocol (M, E, S, I)

When multiple CPU cores maintain private L1 and L2 caches sharing the same physical address space, writes by one core would cause stale reads on other cores without a coherence protocol. The foundational snooping protocol is MESI:

  • Modified (M): The cache line is present only in the current cache and is dirty (modified). Memory in L3/DRAM is stale. The core must flush before anyone else reads.
  • Exclusive (E): The cache line is present only in this cache and is clean (matches memory). The core can write without broadcasting invalidations!
  • Shared (S): The cache line may be present in multiple core caches and is clean. Writes require broadcasting an invalidation (BusRdX).
  • Invalid (I): The cache line contains no valid data. Reads require fetching from peer caches or L3.
07 False Sharing

Multithreading Concurrency Hazard: False Sharing & Line Thrashing

A classic performance catastrophe in multi-threaded systems programming is False Sharing. It occurs when two threads running on different CPU cores modify completely independent variables (e.g. counterA and counterB) that happen to sit next to each other in memory within the same 64-byte cache line.

Even though the threads never access each other's data, the MESI protocol sees writes to the same 64-byte unit. Every write by Core 0 broadcasts an invalidation, forcing Core 1 to dump its L1 cache and re-read the line across the interconnect! This ping-pong effect can degrade multi-core scalability by 80% or more. Systems engineers fix this using 64-byte padding (alignas(64) in C++ or @Contended in Java).

08 Memory Consistency

Memory Ordering Models: x86 TSO Store Buffers & Memory Barriers

CPUs use Store Buffers to hold written values so execution can proceed without waiting for cache line ownership. Under the x86 Total Store Order (TSO) consistency model, writes to memory are globally ordered, but Store-Load Reordering can occur: a local read can execute before an earlier write from the same core has drained from the store buffer to L1 cache.

This breaks classic lockless algorithms (such as Dekker's and Peterson's mutual exclusion algorithms): both cores can write their flag and read each other's flag as 0 simultaneously! Programmers must insert an explicit Memory Fence (MFENCE or smp_mb()) to force the store buffer to drain completely before subsequent loads execute.

Part III

DRAM & NUMA Interconnects

The physical constraints of main memory: DRAM bank row buffer hits, multi-socket NUMA interconnect latency cliffs, and Williams' Roofline model.

09 DRAM Physics

DRAM Physics: Channels, Ranks, Banks, Rows & CAS Latency

Main memory is organized hierarchically: Memory Controllers manage independent Channels connected to DIMM modules containing multiple Ranks and Banks. Each bank is an array of capacitive bit cells organized in Rows and Columns.

Reading data requires activating an entire 8KB row into the bank's Sense Amplifiers (Row Buffer). Timing constraints define real memory speed:

  • Row Buffer Hit ($t_{\text{CL}} \approx 14\text{ ns}$): The requested row is already open. Accessing the column takes only CAS Latency ($t_{\text{CL}}$).
  • Row Conflict / Miss ($t_{\text{RP}} + t_{\text{RCD}} + t_{\text{CL}} \approx 52\text{ ns}$): Must precharge/close the active row ($t_{\text{RP}}$), activate the new row ($t_{\text{RCD}}$), and read the column ($t_{\text{CL}}$). Sequential array traversals maximize row buffer hits!
10 NUMA Interconnect

Non-Uniform Memory Access (NUMA): Socket Interconnect Latency Cliffs

In multi-socket enterprise servers, physical memory is partitioned across sockets in a Non-Uniform Memory Access (NUMA) topology. Each CPU socket contains its own integrated memory controller directly wired to dedicated DDR5 DIMMs.

Accessing Local Memory takes $\approx 65\text{ ns}$ at full bus bandwidth. However, accessing Remote Memory attached to the opposite socket requires routing requests over high-speed point-to-point interconnects (Intel UPI or AMD Infinity Fabric), ballooning latency to 130+ ns and cutting memory bandwidth in half! Systems engineers bind latency-sensitive workloads using numactl --cpunodebind=0 --membind=0 to eliminate cross-socket hops.

11 Performance Modeling

The Roofline Model: Arithmetic Intensity & The Memory Wall

Formulated by Samuel Williams and David Patterson at UC Berkeley, the Roofline Model provides a visual bound on algorithm performance based on Arithmetic Intensity (FLOPs / Byte):

$$\text{Attained Performance} = \min\big(\text{Peak Compute}, \text{Arithmetic Intensity} \times \text{Peak Bandwidth}\big)$$

Algorithms with low arithmetic intensity (such as vector addition or sparse matrix math, $< 1\text{ FLOP/Byte}$) are strictly Memory-Bound: execution is bottlenecked by DRAM memory bus bandwidth, meaning code optimizations to instructions have zero impact. Algorithms with high intensity (dense matrix multiplication, $> 10\text{ FLOP/Byte}$) are Compute-Bound and saturate the ALU pipelines.

Part IV

Systems & Hardware Security

Modern processor interactions with runtime software: hardware prefetchers, Spectre transient side-channels, MMU HugePages, and DVFS power scaling.

12 Hardware Prefetch

Hardware Prefetching: Stream & Stride Detectors

To mask DRAM latency, modern CPUs contain dedicated Hardware Prefetchers in L1 and L2 caches. Prefetchers monitor memory access streams, detecting regular patterns:

  • Stream Prefetcher: Detects sequential ascents or descents through memory lines, requesting future cache lines before the CPU demands them.
  • Stride Prefetcher: Detects fixed step intervals (e.g. iterating every 4th element of an array, stride $+64\text{ bytes}$).

This is the fundamental microarchitectural justification for flat array layouts (such as contiguous vectors or columnar storage) over linked node graphs (pointers): linear layouts trigger 95%+ prefetch hit rates, completely hiding memory latency!

13 Transient Execution

Hardware Security: Spectre Variant 1 & Transient Side-Channels

Discovered in 2018, Spectre (CVE-2017-5753) exposed a fundamental vulnerability in speculative execution. Consider bounds check code:

if (x < array1_size) {
    y = array2[array1[x] * 512];
}

If the branch predictor is trained to believe the condition is true, passing an out-of-bounds index $x$ causes the CPU to speculatively read out-of-bounds secret data and use it to access array2. Even though the CPU eventually realizes the branch failed and squashes the instruction in the ROB, the speculative read left an echo: array2[secret * 512] is now cached in L1 data cache! By timing reads to array2, an attacker recovers secret memory across security boundaries.

14 MMU Hardware

Hardware MMU & HugePages: 4KB vs. 2MB / 1GB TLB Reach

On modern servers with 128GB to 1TB of RAM, standard 4KB pages severely constrain the TLB Reach (the total amount of virtual memory mapped by L1 TLB entries). With 64 L1 TLB entries, 4KB pages cover only $64 \times 4\text{KB} = 256\text{ KB}$ of memory!

High-memory database and storage engines experience up to 30% execution time lost purely to MMU page table walks. By configuring 2MB HugePages, the TLB reach expands $500\times$ to 128 MB with zero code changes, bypassing the Page Table (PT) level and drastically improving memory latency.

15 Power Architecture

Energy-Efficient Computing: DVFS Dynamic Scaling & C-States

Modern processors govern energy consumption through two complementary mechanisms:

  • P-States (Performance): Dynamic Voltage and Frequency Scaling (DVFS). Dynamic power is proportional to $P = C \cdot V^2 \cdot f$. Because voltage scales with frequency, dropping clock speed yields quadratic power savings!
  • C-States (Core Sleep States): When a core has no runnable tasks, it transitions from active execution ($C_0$) through progressively deeper idle states ($C_1$ to $C_6$). In $C_6$, the core is power-gated (0V) and its L1/L2 caches flushed, taking $\approx 40\text{ }\mu\text{s}$ to wake.
